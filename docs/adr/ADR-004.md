# ADR-004 — Three agents plus a critic pass (not nine agents)

- **Status:** Accepted
- **Date:** 2026-07-22
- **Deciders:** Technical lead (Phase 0)
- **Context source:** `CLAUDE.md` (pinned stack), `docs/CHARTER.md` (Agent Architecture), `docs/architecture.md` §5

## Context

The charter enumerates many specialist "roles" — Business Analyst, Process Intelligence, AI Solutions Architect, Automation, Security & Governance, ROI Analyst, Executive Communications, Implementation Planning — and it is tempting to model each as its own autonomous agent. That framing conflicts with the product's core discipline (`CHARTER.md`, `CLAUDE.md`): **every claim must be evidence-linked, assumptions must be labeled, and dollars must be computed deterministically.** More agents means more seams where those invariants can be dropped, more orchestration surface, more latency, more cost, and more nondeterminism — with little added capability, because a modern model given a clear perspective prompt and the right tools can play "ROI Analyst" or "Security reviewer" within one agent step.

The actual pipeline has three natural stages that map to the engagement lifecycle: **learn about the org → analyze and score opportunities → produce executive deliverables** — with a **quality gate** before anything ships.

## Decision

Exactly **three agents plus a critic pass**:

1. **Discovery Agent** — conducts the adaptive interview; retrieves ingested knowledge; records answers as evidence; flags gaps; requests documents.
2. **Analysis & Scoring Agent** — generates candidate opportunities from knowledge + answers; scores each dimension with required evidence (or an explicit assumption flag); proposes ROI **inputs** (never dollars).
3. **Executive Synthesis Agent** — composes deliverables from the knowledge base, every claim carrying evidence references.
4. **Critic pass** — a **step, not a fourth standing agent** — that reviews Scoring/Synthesis output for unsupported claims, assumptions rendered as facts, any LLM-emitted currency, and internal inconsistency. One revise loop, then human review.

The charter's specialist roles are implemented as **prompt perspectives applied inside these three agents** (e.g., the Analysis agent runs an "AI Solutions Architect" and a "Security & Governance" lens over the same context), not as separate services. See the agent contract table in `architecture.md` §5.1.

## Consequences

**Positive**
- **Fewer seams, stronger invariants.** The evidence/assumption/no-$ rules are enforced at three well-defined boundaries plus one gate, not smeared across nine handoffs.
- **Legible orchestration** (ADR-003): the pipeline is a short, sequential TypeScript flow that mirrors the engagement lifecycle and the sequence diagram.
- **Lower latency and cost**, and less nondeterminism, than a many-agent swarm passing messages.
- **Perspectives are cheap to add**: a new lens is a prompt addition inside an existing agent, not a new service, queue, and contract.
- The critic-as-gate gives us a single, auditable place where "is this safe to show a client?" is decided.

**Negative / costs**
- Each of the three agents is "fatter" — its prompt carries multiple perspectives, which needs careful prompt design to avoid the model dropping a lens under load. We manage this with structured outputs that *require* each perspective's contribution.
- Less parallelism than independent specialist agents (though the stages are inherently sequential anyway, so the loss is small).
- If one stage genuinely needs to fan out (e.g., scoring 50 opportunities concurrently), we do that as parallel *calls within* the Analysis agent, not by minting new agent types — a pattern we must remember to reach for deliberately.

**Mitigations**
- Zod-schema'd outputs force every required perspective/field to be present, so "the model forgot the Security lens" fails validation instead of shipping silently.
- The critic pass is the backstop: anything a fattened agent drops (unsupported claim, unlabeled assumption, raw dollar figure) is caught before human review.
- Reopen via ADR only if a concrete capability — not a taxonomy preference — proves it needs its own agent.

## Alternatives considered

- **Nine specialist agents (one per charter role)** — mirrors the charter's vocabulary and maximizes separation of concerns, but multiplies orchestration surface and invariant-drop risk for capability a perspective-prompt already delivers. Rejected as speculative complexity that works *against* the evidence discipline.
- **One monolithic agent** — simplest orchestration, but conflates learning, scoring, and synthesis into one context, making the evidence/critic boundaries impossible to enforce cleanly and the pipeline hard to reason about. Rejected.
- **Two agents (discovery + everything-else)** — collapses scoring and synthesis, but those two have genuinely different outputs (typed scores + ROI inputs vs. narrative deliverables) and different failure modes, so keeping them distinct earns its seam. Rejected in favor of three.

## Compliance / how we'll know it held

- The codebase defines exactly the agents `discovery`, `analysis`, `synthesis`, `critic` in `lib/ai/agents/` — no more.
- Specialist "roles" appear as prompt perspectives / schema fields, not as separate agent modules or services.
- The critic pass runs before any deliverable reaches `status = 'final'`, and its verdict is recorded in `deliverables.critic_notes` / `agent_runs`.
