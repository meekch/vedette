# ADR-003 — Vercel AI SDK for all model calls and orchestration (no LangGraph / LangSmith)

- **Status:** Accepted
- **Date:** 2026-07-22
- **Deciders:** Technical lead (Phase 0)
- **Context source:** `CLAUDE.md` (pinned stack), `docs/architecture.md` §5

## Context

Vedette's AI surface is bounded and well understood (ADR-004): three agents plus a critic pass, each a step with typed inputs and outputs. The hard requirements are not exotic control flow — they are:

1. **Structured, schema-validated outputs** everywhere (scores, ROI inputs, deliverable sections) so we can enforce the evidence/assumption invariants and never let the model free-form a number.
2. **Streaming** the Discovery interview to the FDE in real time.
3. **Tool calling** where tools are thin wrappers over Supabase queries and deterministic domain logic.
4. **Provider flexibility** — we may switch chat/embedding models per the open questions in `architecture.md` §9.
5. Living inside a **Next.js App Router** deployment on Vercel with minimal glue.

The orchestration itself is *sequential and legible* — run Discovery, then Analysis & Scoring, then Synthesis → Critic, persisting between steps. That is plain control flow, not a graph that needs a runtime.

## Decision

Use the **Vercel AI SDK** for every model call and for orchestration. **No LangGraph, no LangChain, no LangSmith** unless a future ADR adds them. Concretely:

- `generateObject` + **Zod** schemas for all structured outputs (extraction, scoring, ROI inputs, deliverable sections). Validation at the SDK boundary forces the model to retry on malformed output.
- `streamText` / `generateText` with `tools` and a bounded step cap for the Discovery interview loop.
- The **orchestrator is ordinary TypeScript** (`lib/ai/orchestrator.ts`) sequencing the three agents + critic. Control flow (if/else, one revise loop) is code, not a declared graph.
- **Provider abstraction** via the SDK's model interface, so swapping providers is a config change, not a rewrite.
- **Observability is our own**: each agent run is written to `agent_runs` (model, tokens, latency, critic verdict). We do not adopt a third-party tracing SaaS in Phase 0.

## Consequences

**Positive**
- One AI dependency, native to the Next.js/Vercel deployment; streaming and route handlers "just work."
- `generateObject` + Zod makes the **evidence/assumption/no-$ invariants enforceable** at the type boundary — the single most important property of our AI layer.
- The orchestration reads like the sequence diagram in `architecture.md`; a reviewer can follow it without learning a graph DSL.
- Provider-swappable, which the open model-choice questions require.

**Negative / costs**
- If orchestration later grows genuinely graph-shaped (fan-out/fan-in, dynamic re-planning, long-running human-in-the-loop resumption, durable checkpoints), hand-rolled TypeScript will feel thin where LangGraph offers structure. We accept that risk now and will reopen with an ADR if it materializes.
- We build our own tracing/eval tooling on top of `agent_runs` instead of getting LangSmith's dashboards for free.
- The SDK is younger and moves faster than LangChain; we pin versions and watch for breaking changes.

**Mitigations**
- The orchestrator is small and isolated; if it must become a graph, it is one file to refactor and the agent contracts (typed I/O) don't change.
- `agent_runs` plus deterministic evals on the scoring/ROI math (pure TS, `tests/`) cover most of what we'd want from a tracing SaaS at this stage.

## Alternatives considered

- **LangGraph** — the right tool *if* we had complex, stateful, cyclic multi-agent graphs with durable checkpointing. We don't (ADR-004 keeps it to three sequential agents + a one-shot critic loop). Adopting it now is speculative complexity, and it partly duplicates what the AI SDK already gives us for structured output and streaming. Rejected for Phase 0; explicitly reopenable via ADR.
- **LangChain (core)** — heavier abstraction stack for capabilities we either don't need or get more cleanly from the AI SDK + our own tools. Rejected.
- **LangSmith** — attractive tracing/eval product, but a third-party data path for prompts/outputs and another vendor. Deferred: we start with `agent_runs` and revisit if home-grown observability becomes the bottleneck.
- **Direct provider SDKs** (Anthropic/OpenAI SDKs) — maximal control, but we'd re-implement streaming helpers, structured-output validation, and provider abstraction that the AI SDK standardizes. Rejected.

## Compliance / how we'll know it held

- No `langchain` / `langgraph` / `langsmith` dependency in `package.json` without a superseding ADR.
- Every structured model output has a Zod schema in `lib/ai/schemas`; no code path renders a model-emitted currency value (the ROI calculator in `lib/roi` is the only source of dollars).
- `agent_runs` is populated for every agent invocation.
